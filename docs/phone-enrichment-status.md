# Обновление фотографий и карточек телефонов

Контрольная точка: 10 сентября 2026 года. Основной репозиторий до переноса: `1fd8de9`.

## Этап 1 — материалы проверены

- 38 моделей: 15 Xiaomi/POCO/REDMI и 23 HONOR/HUAWEI/OnePlus.
- 122 расцветки, 170 оригинальных файлов. Проверены основные фотографии и дополнительные ракурсы; снимки не перекрашивались и не генерировались.
- Галереи привязаны к конкретной расцветке. В частности, чёрный и красный POCO F9 Ultra больше не используют общий коллаж.
- У 23 ранее незаполненных моделей подготовлены описания, основные особенности и характеристики с оговорками о рынке поставки.
- Дополнительно сверены HONOR Magic V6, OnePlus 13/Nord 5 и HUAWEI Mate XT; у Mate 80 Pro указан телемакрообъектив 48 МП по официальной спецификации.
- Источники и SHA-256 каждого оригинала: `prisma/data/phone-enrichment-photo-sources.json`. Все фото с сайтов производителей, кроме Orange у POCO X8 Pro Max — источник продавца указан отдельно.
- Два неиспользуемых черновых файла `redmi-note-15-pro-5g-titanium{,-side}.png` остаются только в рабочей папке и не входят в поставку или таблицу размеров.

## Этап 2 — код и безопасное обновление

Выполнено: 49 тестов прошли, TypeScript и production-сборка Next.js успешны.

- Вместо «Под заказ»/«Уточняйте цену» используется «Уточняйте у менеджера», без двойного сообщения в карточке.
- `prisma/scripts/sync-phone-enrichment.ts` обновляет только опубликованные целевые телефоны. Скрытые и отсутствующие товары не публикует.
- Существующие цены, наличие, регионы и идентификаторы не перезаписываются. Новые варианты создаются без выдуманных цен и наличия.
- Нераспознанный вариант с ценой или реальным наличием останавливает всё обновление до записи. Устаревшие пустые варианты перемещаются в скрытый архив с сохранением ID. Старый импортёр выставлял `inStock=true` даже пустым заявкам: такие заглушки распознаются только по точному совпадению исходных полей и `rawLabel`, при `price=null`. Изменённые поставщиком записи этим исключением не затрагиваются.
- Перед записью создаётся резервная копия целевых товаров в `backups/phone-enrichment/`. Есть `--dry-run`; запись выполняется одной транзакцией.
- Тесты проверяют цветовые галереи, оригинальность файлов, подписи цен, сохранность предложений и повторный запуск.

## Этап 3 — обновление сервера

Локальная проверка завершена. Серверная база не проверялась и не изменялась: её проверяет отдельный `--dry-run` ниже. Результат в браузере на сервере нужно проверить после применения обновления.

Из папки серверного проекта, где находятся `docker-compose.yml` и `.env.docker`, выполнять по одной команде. При любой ошибке остановиться и сохранить вывод.

```sh
git pull --ff-only origin main
docker compose --env-file .env.docker build app migrate
docker compose --env-file .env.docker up -d --no-deps app
docker compose --env-file .env.docker run --rm migrate npx tsx prisma/scripts/sync-phone-enrichment.ts --dry-run
docker compose --env-file .env.docker run --rm migrate npx tsx prisma/scripts/sync-phone-enrichment.ts
```

Сначала запускается образ с новыми фотографиями, затем обновляются ссылки в БД: это не оставляет старое приложение со ссылками на отсутствующие файлы. После успешного dry-run последняя команда применяет данные. Меню кешируется максимум на минуту; страницы товаров читают актуальную базу.

В выводе должны быть целевые модели и в конце число обновлённых моделей. Если видны только `SKIP`, либо ошибка о нераспознанном предложении с ценой/наличием, не запускать обходные команды. Требуется проверить конкретную запись, не удалять товары или тома.

Резервная копия сохраняется в постоянном Docker-томе `catalog_backups`, в каталоге `/app/backups/phone-enrichment` контейнера `migrate`, и не выдаётся посетителям сайта. Старые пустые варианты переносятся в скрытый архив, а не удаляются. Их можно восстановить по ID/резервной копии.
